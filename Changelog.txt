- v1.1.2
### Bug Fixes
- Play through a script extender (SFSE, SKSE64, F4SE, ...) when the bottle's Steam isn't running yet waits until Steam has signed in. Before, the game could start before Steam was ready, restart through Steam without the script extender, and the Play button went back to Play while the game ran
- While Play waits for Steam, the button shows Stop, and Stop cancels the launch. If Steam is in offline mode, or has been running without signing in, Play doesn't wait

- v1.1.1
### Bug Fixes
- With the Change Version tab open, selecting a Creation no longer leaves the previous mod's Nexus files on screen. The tab says the mod is a Creation and points to Open on Creations

- v1.1.0
### macOS
- System Information shows the macOS version, run mode and installed CrossOver builds instead of the Linux distribution, libc, Flatpak/AppImage and desktop-session rows
### Additions
- Creations downloaded from the in-game Creations menu become mods on the next deploy: one mod per Creation, named after it, in the Creations category and enabled at the top of the mod list. Mods you already made for a Creation are reused and never renamed
- Deploy runs by itself when a game started with Play exits and its Creations changed. If they changed while Caelumite wasn't running, a notice at startup says to deploy
- Updates from the Creations menu go into the same mod: its version and Updated date are refreshed, the xEdit flag Restore would set is cleared, and plugins or archives the update dropped are moved to creations_backup/ next to your profiles
- Creation plugins show the Creation's title and version as a tooltip in the plugin list
- "Open on Creations" in the mod list's right-click menu opens a Creation mod's page on creations.bethesda.net
### Bug Fixes
- Restore no longer flags a plugin as edited in xEdit when the game rewrote it with identical bytes (for example when a Creation is downloaded again)

- v1.0.0
Initial release of Caelumite, a macOS fork of Amethyst Mod Manager 2.5.5 by ChrisDKN.
### macOS
- Games run in CrossOver bottles: bottles, and the Windows Steam inside them, are detected automatically
- Play, Run EXE, wizards and tools run in the game's bottle
- Mods deploy as hardlinks by default
- A self-contained, signed and notarized Caelumite.app for Apple silicon, with its own name, icon and native menu bar (Settings, Edit, Window, Help)
- Native macOS open and save panels
- nxm://, ror2mm:// and modl:// links open in Caelumite
- Credentials are stored in the macOS Keychain
- Window title bars follow the theme
### Additions
- A detected script extender (SFSE, SKSE64, F4SE, ...) is the default Play entry, shown as e.g. "Starfield (SFSE)". It starts the bottle's Steam first; the game entry starts the game without it
- scripts/import_mo2.py imports a Mod Organizer 2 instance: mods, overwrite, load order and separators, as APFS clones
- The mod list defaults to MO2's order (lowest priority at the top)
### Changes
- Wine DLL overrides are written through the bottle's Wine, so a running Wine can't overwrite them
- Nexus requests identify as Caelumite. Nexus login stays off until Nexus registers Caelumite; a personal API key works for testing (see docs/NEXUS.md)
- Game handlers, wizard plugins, translations and other resources sync from Caelumite's own Resources branch
- Linux-only features are hidden on macOS: Wayland, LSFG, MangoHud, the VFS deploy method, winetricks and Proton component installers, Wabbajack, and the wizards for Linux-native or Proton-only tools
- Upstream's Ko-Fi and Endorse buttons, Crowdin link and LoversLab login (only Wabbajack used it) are removed
- App updates come from Caelumite's GitHub releases: the app offers to download the newest notarized DMG
### Bug Fixes
- FOMOD: options are no longer dimmed when an unmet condition wouldn't make them recommended
- Nexus update checks read MO2's installed file ids from meta.ini, so imported mods no longer report false updates
- Linking plugins.txt into a tool prefix no longer fails for Starfield and Oblivion Remastered (xEdit, BethINI, PGPatcher and other wizards, Run EXE)
- The "Catalog has no raw manifest" warning lists each missing mod once
